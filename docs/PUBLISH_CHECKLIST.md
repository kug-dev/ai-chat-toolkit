# Before publishing to GitHub

- [ ] Choose a license. Until then, keep the repository without a `LICENSE` file and do not label it open source.
- [ ] Decide whether the repository should be public or private for the first preview.
- [ ] Review the final diff and the generated userscript bundle.
- [ ] Run the complete validation commands from the README.
- [ ] Confirm no personal names, account IDs, absolute home-directory paths, API keys, cookies, chat archives, or generated reports are committed.
- [ ] Enable private vulnerability reporting if available.
- [ ] Add a short project description and topics such as `chatgpt`, `claude`, `gemini`, `conversation-archive`, `tampermonkey`, `python`, `local-first`, and `text-analysis`.
- [ ] Make the first release a clearly labelled beta; site extraction depends on upstream web app behavior.
- [ ] Publish only synthetic test data, never a real chat archive.
